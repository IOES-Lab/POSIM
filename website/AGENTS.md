# Public documentation

These rules apply to user-facing README files, public guide sources and their generated pages.

- Describe the current product in present tense. Readers have no knowledge of earlier versions.
- Keep release history, implementation changes, review dates, PR progress and validation narratives in internal engineering records.
- State what a feature does and how to use it. Avoid defensive contrasts or unrelated statements about what it is not.
- Keep necessary prerequisites, limitations, data assumptions, measured-versus-target distinctions and author/license notices.
- Use short sentences and one topic per paragraph. Explain the method in prose; list distances, speeds, limits, units and defaults as bullets or tables.
- Use natural Korean. Write 설치형 앱 for standalone/desktop application, 상부 덮개 for the vehicle canopy and 선행 차량 / 추종 차량 for the voyage pair.
- Name current colours and settings directly. Never use previous/original appearance as the reader's reference.
- Keep English and Korean facts aligned, including links, units and values. Preserve working commands and cross-page anchors.
- Verify numbers and supported behaviour against current source. Give shared facts one authoritative guide; link to it instead of duplicating them in generators.
- Update source files, regenerate published HTML and run documentation checks. Review desktop and mobile output.
