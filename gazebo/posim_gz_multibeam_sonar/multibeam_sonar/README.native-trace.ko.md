# 네이티브 소나 입력의 제한된 기록

[English](README.native-trace.md)

이 선택형 진단 기능은 WGPU 호출에 실제 전달되는 입력과 전체 복소수 출력을
기록합니다. 렌더 시작과 레이 콜백에서 렌더링 노드의 자세도 기록합니다.
콜백 자세와 캡처 시각은 복제된 거리 스냅샷과 함께 비동기 계산 스레드로
전달됩니다. 기본 센서 동작에서는 파일을 기록하지 않습니다. Rust C ABI와
발행되는 ROS 토픽은 같습니다.

프로세스마다 새로 만든 쓰기 가능한 디렉터리를 지정합니다. 기존 파일은
덮어쓰지 않습니다. 제한은 **최대 4프레임, 합계 40 MiB**입니다. 잘못된 설정,
저장 공간 부족, 미완성 쓰기와 한도 도달은 원래 계산 호출과 반환 포인터를
바꾸지 않습니다. 계산에서 예외가 발생하면 미완성 파일을 닫고 원래 예외를
호출자에게 전달합니다.

```sh
export POSIM_SONAR_NATIVE_TRACE_DIR=/path/to/new-empty-directory
export POSIM_SONAR_NATIVE_TRACE_START_NS=20000000000
export POSIM_SONAR_NATIVE_TRACE_SPACING_NS=20000000000
```

선택 항목인 시작 시각과 간격은 음수가 아닌 정수형 시뮬레이션 나노초입니다.
각 시각 경계 이후 처음 실행되는 유효 호출을 기록합니다. 간격이 0이면 강도,
형상, 반사값의 유효성으로 걸러내지 않고 처음 4개 호출을 기록합니다. 설정은
기록기 수명 동안 고정됩니다. 기록을 끄려면 프로세스 시작 시 디렉터리 변수를
설정하지 않습니다. CPU·CUDA 백엔드는 WGPU 기록을 생성하지 않습니다.

## 기록 형식

파일 이름은 `sonar-native-0.bin`부터 `sonar-native-3.bin`까지입니다. 정수와
실수는 리틀 엔디언 형식을 사용합니다. 고정 헤더의 Python struct 형식은
`<8sI4I10f2QB`입니다.

- 8바이트 식별자 `PSNWG001`과 UTF-8 메타데이터 길이.
- uint32 4개: 빔 수, 수직 레이 수, 주파수 표본 수, 레이 건너뛰기 수.
- float32 10개: 음속, 최대 거리, 음원 준위, 감쇠, 이득, 대역폭, 보정 합,
  면적, 수평 시야각, 수직 시야각.
- uint64 2개: 프레임 번호, 시드. 이어서 디버그 여부 1바이트.

헤더 뒤에는 JSON 메타데이터가 있습니다. 캡처 시각, 렌더링 노드 이름,
콜백 시 센서의 월드·로컬 자세, 부모 노드의 월드 자세, 렌더 시작 시 센서의
월드 자세와 시각을 담습니다. 자세 순서는 XYZ 위치와 WXYZ 쿼터니언입니다.
`context_source=render_node`는 렌더링 노드 관측을 뜻합니다. 오프라인 입력
재생의 가상 자세는 별도 문맥 이름을 사용합니다. 유한하지 않은 자세 성분은
잘못된 JSON 숫자 대신 `{"f64_bits": <uint64>}`로 원래 비트를 보존합니다.

이후 연속된 float32 배열은 다음 순서입니다.

- 거리 `[빔, 레이]`, 백엔드 법선 `[빔, 레이, 3]`.
- 반사율 `[빔, 레이]`, 빔 보정 `[빔, 빔]`, 창 함수 `[표본]`.
- 전체 복소수 출력 `[빔, 표본, 2]`. 마지막 차원은 실수부·허수부입니다.

마지막 8바이트는 `COMPLETE`입니다. 기록을 사용하기 전에 예상 바이트 수,
차원과 끝 식별자가 모두 맞는지 확인해야 합니다. 빈 출력, 예외, 중단되거나
실패한 쓰기는 미완성 기록을 남깁니다. 실패 기록을 보존하고, 파일 이름만으로
캡처 성공을 판단하지 않습니다.

## 검증 범위

`test/NativeTrace_TEST.cc`는 인자·포인터 보존, 정확한 IEEE 배열 비트,
스레드별 문맥과 기록 제한을 검사합니다. CMake의 `bounded_native_trace`
검사는 C++17 표준 라이브러리만 사용하며 릴리스 빌드에서도 검증문이 활성화됩니다.

주어진 거리 배열의 재생 검사는 입력·출력 비트 일치를 확인할 수 있습니다.
실제 렌더러의 거리·자세·시각 일치나 SLAM 지도 정확도를 입증하지는 않습니다.
실제 캡처를 발행된 전체 원시 영상·시각과 연결하고, 기록한 자세에서 장면의
첫 교차 거리와 실제 렌더러 거리 배열을 비교한 뒤 음향 알고리즘의 문제인지
판단합니다.
